# CEMM 2.0.0 Release Validation

This checklist covers gates that source tests cannot honestly prove. Perform it
against the exact signed artifacts that will be attached to the 2.0.0 release,
using a disposable GitHub repository and a disposable CurseForge instance.

## Automated gates

- [ ] `master` is pushed and all GitHub Actions jobs pass.
- [ ] Frontend lint, typecheck, and static generation pass.
- [ ] Rust formatting, clippy with warnings denied, and all tests pass.
- [ ] Sidecar lifecycle tests pass on Windows, macOS, and Linux.
- [ ] The release workflow produces signed updater artifacts and `latest.json`.
- [ ] MSI, NSIS, macOS, and Linux bundles are attached to the same release.

## Native startup and lifecycle

Test each supported platform with the produced release artifact:

- [ ] Install and launch CEMM normally; no terminal window appears.
- [ ] Confirm the dashboard, packs, settings, native dialogs, and window controls.
- [ ] Confirm a sidecar child exists only while CEMM is running.
- [ ] Close CEMM while idle and confirm the child exits promptly.
- [ ] Force-stop the sidecar, perform a harmless read/scan action, and confirm the
      next request starts a replacement child or reports a clear failure.
- [ ] Confirm a second CEMM launch has no stale pipe, port, or daemon conflict.

## Disposable GitHub distribution round trip

- [ ] Store a token through the normal keyring UI; confirm it is not logged.
- [ ] Publish a small full update and watch correlated progress reach 100%.
- [ ] Publish a config-only update.
- [ ] Download both update codes through the normal user flow.
- [ ] Verify invalid repository, invalid code, revoked token, rate-limit, and
      offline failures produce actionable messages and do not cache success.
- [ ] Remove the disposable token and repository data after validation.

## Disposable install and recovery

Never use a real player instance for this gate.

- [ ] Copy a small test instance into a disposable directory.
- [ ] Install a full update and verify add, update, remove, disabled-addon, config,
      and `cemm-manifest.json` results.
- [ ] Install a config-only update and verify every add-on remains untouched.
- [ ] Lock a destination file during finalization and verify automatic rollback
      restores all original files.
- [ ] Terminate CEMM during finalization, relaunch, retry the install, and verify
      the interrupted transaction is recovered before new work begins.
- [ ] Confirm `.cemm-transaction` is absent after success or successful rollback.

## Updater and final release

- [ ] Install the prior stable version and update to 2.0.0 through the updater UI.
- [ ] Verify the downloaded signature against the configured public key.
- [ ] Confirm the application restarts and the local sidecar starts afterward.
- [ ] Review release notes for the architecture change and recovery behavior.
- [ ] Tag and publish only after every applicable checkbox has evidence.
